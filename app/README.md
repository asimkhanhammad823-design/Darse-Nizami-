# Dars-e-Nizami — Student App (Phase 3, Flutter/Android)

This is the student-facing app: Darja → Kitab → Lecture browsing, background
audio playback with lock-screen controls, and a live "Safa" (page) display
driven by the page markers set in the admin panel.

The Dart source code (`lib/`) and `pubspec.yaml` are already written. What's
missing is the native Android project scaffolding (`android/` folder), which
must be generated by the Flutter SDK on your own machine — it can't be done
from this sandbox.

## 1. Install prerequisites (one-time, on your PC)

1. Install **Flutter SDK**: https://docs.flutter.dev/get-started/install/windows
   (pick Windows). Follow the installer's PATH setup step.
2. Install **Android Studio**: https://developer.android.com/studio — during
   setup let it install the Android SDK, Android SDK Platform-Tools, and an
   emulator image (or plan to test on a real phone via USB).
3. Verify everything is wired up:
   ```powershell
   flutter doctor
   ```
   Fix anything it flags with a ✗ (usually: accept Android licenses with
   `flutter doctor --android-licenses`).

## 2. Get this code and generate the Android project

```powershell
cd C:\Users\Aasim\dars-project\darse-nizami-
git pull origin claude/audio-dars-e-nizami-l5855z
cd app
flutter create --org com.darsenizami --project-name dars_nizami .
```

Running `flutter create .` inside a folder that already has `pubspec.yaml`
and `lib/` is safe — it only **adds** the missing `android/`, `ios/`, etc.
folders, it does not overwrite our existing Dart code.

```powershell
flutter pub get
```

## 3. Edit the generated AndroidManifest.xml

Open `android/app/src/main/AndroidManifest.xml` in a text editor. You need to
add permissions (for internet access and background audio) and two
components (for lock-screen media controls), which `flutter create` doesn't
add by default.

Add these permission lines as direct children of the outermost `<manifest>`
tag (before `<application ...>`):

```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.WAKE_LOCK" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />
<uses-permission android:name="android.permission.POST_NOTIFICATIONS" />
```

> `INTERNET` matters especially — Flutter's template only adds it
> automatically for debug/profile builds, not for the release build we'll
> ship in Phase 4. Without it, the release APK cannot reach the Worker at all.

Then, inside the `<application ...> ... </application>` block (anywhere
alongside the existing `<activity>` tag), add:

```xml
<service
    android:name="com.ryanheise.audioservice.AudioService"
    android:foregroundServiceType="mediaPlayback"
    android:exported="true">
  <intent-filter>
    <action android:name="android.media.browse.MediaBrowserService" />
  </intent-filter>
</service>

<receiver
    android:name="com.ryanheise.audioservice.MediaButtonReceiver"
    android:exported="true">
  <intent-filter>
    <action android:name="android.intent.action.MEDIA_BUTTON" />
  </intent-filter>
</receiver>
```

Save the file.

## 4. Run it

Plug in an Android phone (with USB debugging enabled in Developer Options)
or start an emulator from Android Studio, then:

```powershell
flutter devices
flutter run
```

The app is pre-configured to talk to the deployed Worker
(`https://dars-worker.ateekkhan-dars.workers.dev`). To point it at a
different Worker URL later, run:

```powershell
flutter run --dart-define=WORKER_BASE_URL=https://your-worker.workers.dev
```

## 5. What's implemented

- Login screen (access code → token, stored in `flutter_secure_storage`)
- Home → Darjas, tap into Books, tap into Lectures
- Player screen:
  - Streams audio directly from the Worker's short-lived signed URL (never
    downloaded to disk — `just_audio`'s default `AudioSource.uri` streams
    without disk caching)
  - Big "Safa" (page) number that updates live from the page markers, per
    the page-display rule (largest marker time ≤ current position; nothing
    shown before the first marker)
  - Play/pause, 15s back/forward, seek bar, speed control (1x/1.25x/1.5x/2x)
  - Background playback + lock-screen controls via `just_audio_background`
  - If the signed URL expires mid-session (~120s) and a seek/request fails,
    the app transparently fetches a fresh URL and resumes from the same
    position
- `FLAG_SECURE` set once at app startup (`main.dart`), which covers every
  screen since a Flutter app runs in a single Android Activity — blocks
  screenshots and screen recording at the OS level
- No download or share button anywhere; audio is only ever played from the
  in-memory signed URL

## Not implemented (per the spec's "honest limitations")

- Screen-recording/casting *detection* (marked optional/hard in the spec) —
  `FLAG_SECURE` already blocks the recording itself, which covers the actual
  requirement.
- iOS — out of scope per the spec.
